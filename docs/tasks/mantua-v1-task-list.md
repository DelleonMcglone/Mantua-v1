# Mantua v1 — Agent-Driven Sports Prediction Market Task List

---

## 🚦 THE LAUNCH STANDARD

The Arc Mainnet MVP is **not complete** until this loop works end-to-end:

> **User opens Mantua → finds NFL game → asks agent for analysis → agent automatically retrieves sports + market + onchain intelligence → agent provides probability/evidence/risk → user buys YES/NO in ≤3 taps → transaction is gasless → trade is immediately confirmed → position updates in real time → agent monitors the position → agent can sell/hedge before resolution → market resolves correctly → user receives USDC.**

That is the core Mantua product. Everything else — combos, social agents, marketplace distribution, advanced LP analytics — is downstream of making that loop exceptional.

---

## 🎯 PRODUCT DEFINITION & POSITIONING (Source of Truth)

**Product definition:** Mantua on Arc Mainnet — Circle's stablecoin-native L1, where USDC is also the gas token (Arc Mainnet chain 5042 for launch; Arc Testnet 5042002 for development). Core product: sports prediction markets (NFL at launch). Primary UX: AI agents. Execution: agent-controlled positions. Liquidity: USDC. Programmability: Uniswap v4 hooks. Infrastructure: Circle Wallets, USDC, x402.

**Mantua is an agent-native prediction market with programmable liquidity and execution.**

- The **prediction market** is the wedge.
- The **agents** are the interface.
- The **hooks** are the infrastructure moat.

Primary areas: Protocol • NFL prediction markets • Circle Agent / AI agents • Hooks • Analytics • Portfolio management.

**Agent architecture separation (governs every agent task below):**

> **Skill = knowledge • Tools = capabilities • Circle Agent Wallet = financial authorization • Mantua contracts = market enforcement • User = permission and risk control.**

**The user never needs to know any of this is happening.** Their mental model:
`Connect bank → Deposit dollars → Get Mantua balance → Ask your agent → Agent trades → Withdraw dollars.`
Behind it: `USD → USDC → Circle → Arc → Mantua smart contracts → settlement → USDC → USD`

**Core UX loop to nail first:** `Discover → Analyze → Trade → Monitor → Exit/Settle`

**Two-layer experience:**

| Layer           | Qualities                                        |
| --------------- | ------------------------------------------------ |
| Consumer layer  | Fast • Simple • Gasless • Transparent            |
| Pro/agent layer | Data-rich • Programmable • Automated • Real-time |

**Overarching principle:** _Simple on the surface. Programmable underneath._ A user opens Mantua, finds a game, asks the AI agent for analysis, places a position in three taps, and monitors it in real time — without understanding blockchain infrastructure, gas, liquidity mechanics, or the Dynamic Market Hook. Sophisticated users open the same market and drill into pricing, volume, liquidity, historical data, fees, and execution mechanics.

## 🏈 PHASE 3: Sports Data Layer (Sportradar) 🔴

> Server-side layer that continuously ingests licensed NFL data, normalizes it, stores it, and exposes it to the Mantua UI **and** the Mantua agents. The user never supplies an API key, connects a sports-data account, uploads sports data, or configures an integration. Treat the provider like Circle: **mission-critical infrastructure** — never free APIs in production (prototyping only). Data must be **accurate + fast + licensed + available + consistent**. If a market resolves incorrectly because the provider missed an event, that's a financial-market-integrity problem. Do NOT have the agent hammer Sportradar directly per request: `Sports Provider → Mantua ingestion → Canonical Mantua sports database → UI + Agent`.

## 🪝 PHASE 5: Dynamic Market Hook & Fee Model 🔴

> Adjust the hook codebase to meet Mantua's standards and formula; deploy to **Arc Mainnet**.

### The Fee Model (spec — authoritative)

- **Regular season: 0% trading fees** — maximize user adoption, liquidity, market activity, and network effects.
- **Playoffs: fees are introduced.**
- **Dynamic fee range: 0.10%–0.70%**, controlled by the Dynamic Market Hook.
- **Maximum fee: 0.70%** — Mantua never exceeds this ceiling.
- Fee varies by market conditions: **liquidity, volatility, trading activity, market uncertainty**.
- **Highest fee at p ≈ $0.50** (50/50), where uncertainty is greatest; contracts closer to $0 or $1 carry substantially lower fees.

**Formula:** `Fee = C × fee rate × p × (1 − p)`
where `C` = number of contracts traded, `fee rate` = Mantua's dynamic rate capped at 0.70%, `p` = contract price/probability. `p × (1 − p)` is maximized at p = 0.50, so 50/50 trades carry the highest effective fee, declining toward 0%/100%.

## ⚠️ CRITICAL IMPLEMENTATION RULES

1. **Arc Mainnet only (5042) in production** — Arc Testnet (5042002) for development only; no testnets in production code paths; dev against Arc Testnet and Arc Mainnet forks.
2. **Chain identity is invisible** — no chain selector, no chain badges, no network prompts. Ever.
3. **Gasless is non-negotiable** — no user or agent flow may ever require managing gas; Arc charges gas in USDC, and it is sponsored so users never see it.
4. **0.70% fee ceiling is immutable** — Mantua never exceeds it; regular season is always 0%.
5. **Users see the exact fee before confirming** — every trade, every time; the UI fee calculation matches the hook calculation with no quote/execution discrepancy.
6. **Licensed data only in production** — free sports APIs for prototyping only; a missed event that mis-resolves a market is a financial-integrity incident.
7. **Users never supply data or API keys** — no sports-data accounts, no integrations, no uploads. "Who should I buy?" just works.
8. **No duplicate execution logic** — humans and agents trade through the same shared modules (DRY).
9. **Always confirm onchain** — wait for the receipt, store the transaction in DB, then show success; every user and agent transaction produces an activity record.
10. **Agents operate under user-defined policies** — budget-capped, permissioned, auditable, kill-switchable; agents can never modify their own limits, switch wallets or chains, split transactions, or route around wallet policy.
11. **The LLM never makes unrestricted blockchain calls** — always `LLM → structured tool call → application validation → wallet policy → transaction construction → contract validation → blockchain`; external text (feeds, news, social, user content) is always untrusted data.
12. **Explicit confirmation only** — a fresh simulation precedes every execution; a unique authorization ID is required at execution; "maybe" / "looks good" / "interesting" never authorizes a trade; initial production mode is USER_TESTING (always ask), with autonomous execution gated on user testing.
13. **Probability types never conflate** — market-implied, agent/model, and external probabilities are always distinguished; agent predictions are never presented as certainty; live analyses always show data freshness.
14. **Reliability rises with load** — live-game hot paths get the strictest latency/error budgets, not the loosest.
15. **Inherited engineering standards hold** — 150-line file cap, TDD, pinned deps, no secrets, no TODOs, TypeScript strict, docs updated with code.

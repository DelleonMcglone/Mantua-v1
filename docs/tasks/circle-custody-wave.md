## Success Criteria

- [ ] Every executing path reports success only from a terminal, verified state: no HTTP response, audit row, spending record, portfolio transaction, or agent position may finalize from a `SENT` state — the sync poll fix makes the API honest now, the verified webhook finalizer makes it durable, and both are idempotent at the same key (C-015)
- [ ] Gas Station sponsorship is consumed and verified: the policy the operator configures is the policy the code uses, production hard-fails when it is missing or unbound, and the runbook carries the console step (C-017)
- [ ] Every path that can move money checks the spending cap and then records the intent server-side; a price-feed failure is fail-closed — no feed, no trade (C-019)
- [ ] The kill-switch actually stops the money: the cron/GET money paths refuse when engaged and the toggle takes effect at runtime without a redeploy (C-020)
- [ ] Rate limits survive a lambda recycle via a shared store — per-instance counters are gone, whatever the store choice (C-021)
- [ ] `agent/` and every `AGENT_PRIVATE_KEY` reference are deleted; the operator has revoked/rotated the key and the runbook records the git-history caveat (C-018)
- [ ] Approvals are bounded to the requested trade size — no `MAX_UINT256`/`MAX_UINT160/48` allowances remain on agent paths (C-022)
- [ ] The C-ledger lives in-repo with every status citing its evidence, D-106 defines x402 scope behind the hardening gate, zero stale CDP references remain in the touched roadmap rows, and the D-110 scoreboard reflects reality (this docs item)

## Failure Conditions

- Any caller reports success from a pending or unconfirmed outcome — including a bounded-timeout path that gives up waiting and returns a hash
- A webhook redelivery, or a poll/webhook race, records an outcome twice
- A cap check passes on a CoinGecko miss, or a money path still skips the check-then-record sequence
- The kill-switch engages but a money cron still trades, or engaging it still requires a deploy
- The rate-limit "shared" store is per-instance again under a different name
- `agent/` is ported onto the rails instead of deleted, or is deleted without the operator key revocation recorded
- An approval is bounded to "whatever the last trade needed" instead of the requested amount
- A ledger row status flips here without its evidence anchor flipping with it
- x402 build work starts before the hardening wave lands — violates the locked D-106 gate
